# 综述写作规范 · 体系卷（通用快照版）

> 版本：v3.2-clean（2026-11-05），对齐源 skill v3.2：§15 增案例聚合、整体回顾、两级冲突与进度写回纪律。本卷管**机械运转**——数据怎么搬、编号怎么排、台账怎么写、脚本怎么跑、文件怎么落盘、对账能不能对上。判据一律是「对账对不对得上」，不是「读起来站不站得住」。
> 学术判断（正文措辞、论断强度、概念定义、段落结构、忠实性判断）见 **`survey-writing`** 卷；两卷之间的交接物见 `skills/_shared/handoff.md`。
> 条文准入同受 `survey-writing` §0 约束：新条须有事故病例，无病例不立条。

## 部署约定（快照版新增）

1. **病例要在你自己的项目里重建。** 每条条文只给匿名线索。建议落到 `reports/cases/`，每个病例记：触发场景、错在哪、怎么发现的、哪条条文由此长出。
2. **脚本以本 skill `scripts/` 下的版本为准**。全部走免费接口；每次查询的原始返回逐条落盘 `reports/_raw/` 留痕，判定不落盘不算完成。
3. **密钥只走环境变量**，见仓库根目录 `KEY_SETUP.md`。任何脚本都不得硬编码 key；缺 key 时脚本直接报错退出，不得降级为「查询无果」。
4. **首次使用或换机器先体检。** 在项目根目录跑 `python .claude/doctor.py`（`python3` 视系统而定）；缺 Python／pandoc／Zotero 按报告提示处理，配置 AMiner／Zotero 密钥跑 `python .claude/doctor.py --configure`。体检只读，不会改文献库。
5. **每日监控是可选模块。** 需要时跑 `python <skill>/scripts/daily/init_daily.py --workdir <项目>/daily`，按 `references/daily-lit.md` 填配置，先跑 `daily/check_config.py` 体检，再建定时任务。日报只分诊、不入账；纳入仍走 §7／§8。

## 6A. 批量作业纪律

管束对象：跨会话、多批次生产型任务（提取、投影、搬运批）。

1. 任务卡四要素：输入（路径+行区间）/产出（落盘路径）/纪律（枚举与禁令）/对账行格式；缺一不开工。
2. 每批输出对账行（条数/冲突数/[U]数/[待裁决]数）；冲突≥1 熔断报告。
3. 交付以落盘文件为准，会话内长表不算正式版本。
4. 批次完成登记 `docs/progress.md`（日期、范围、产物路径、遗留数）。
5. 卡片引用的附件必须随卡落盘，禁止指向仅存在于对话中的文本。病例：曾有一版修订包正典仅存对话，落盘时一度要靠重构建。
6. 冻结对象纪律：冻结对象清单与解冻条件以项目执行文件的冻结标记为准；冻结期内作业遇冻结对象，原值照搬并登记，禁就地修改；解冻后的重排按执行文件声明的机制一次完成，禁分次重排。病例：编号冻结期内分次重排曾造成漂移；正面样例：结构轮不动号、压缩轮一次重编。层：流程（§6 组）。

## 7. 文献核验脚本

存在性验证脚本放在本 skill 的 `scripts/` 下（工作权威随项目改进，任务收尾时同步回本目录存档）。

### 7.1 调用顺序与分工

| 顺序 | 脚本 | 何时调用 | 覆盖范围 |
|------|------|---------|---------|
| 1 | `verify_round1.py` | 首选，批量跑全部条目 | Crossref DOI 层（`works/{DOI}`）；DOI 404 或无 DOI 时转 Crossref 书目检索层；`10.48550/arXiv.*` 前缀走 arXiv API 层 |
| 2 | `aminer_search.py` | 仅处理上一层输出 `PENDING_AMINER` / `REVIEW_CANDIDATES` 的条目 | AMiner 检索（完整标题、主标题、第一作者+标题逐级尝试，命中阈值相似度 ≥ 0.85），常用于中文文献、无 DOI 老文献、存疑条目 |
| 3 | `arxiv_curl.py` | `verify_round1.py` 的 arXiv 层返回 `API_ERROR_406` 时 | 同一 arXiv API 改经 curl 发起（arXiv 对 Python urllib 的 TLS 指纹间歇返回 406，curl 通常正常） |
| 4 | `cite_coverage.py` | 参考文献表定稿后 | 正文引用覆盖核对（写作卷 §4.1），区间展开、占位剔除、token 与实体分报 |
| 5 | `faithfulness_check.py` | 证据表成表后／交付前 | 忠实性核对证据行的机械校验（口径见写作卷 §4.2） |

- 用法：
  - `python verify_round1.py <entries.json> <out.json> [start] [end]`
  - `python aminer_search.py <entries.json> <out.json> <verify_out1.json> [<verify_out2.json> ...]`（需环境变量 `AMINER_API_KEY`）
  - `python arxiv_curl.py <n1> <n2> ... <out.json>`（条目号取自脚本同目录、`entries_rest.json` 格式的文件）
  - `python cite_coverage.py <manuscript.md> [-m "# 参考文献"] [-n 期望条数] [-o report.txt]`
  - `python faithfulness_check.py <证据表.md> [-c <manuscript.md>] [-o report.txt]`；`--template` 印空表头
- entries JSON 条目格式：`{"n": 编号, "doi": "...", "arxiv": "..."（可选）, "raw": {"authors": [...], "etal": bool, "title": "...", "journal": str|null, "volume": str|null, "issue": str|null, "pages": str|null, "year": int|null, "month": str|null}, "note": "..."}`。
- 判定阈值不得为凑命中而下调：Crossref 书目自动 resolve 须相似度 ≥ 0.92 且第一作者相符，0.75~0.92 只列为候选；AMiner ≥ 0.85 才算命中。无出处字段的同题记录（引文图谱幽灵记录）不作为存在性证据。
- 检索词链必须完整记录（每一层的策略与查询串），供 ❌/⚠️ 条目写证据链与人工复查。
- `verify_round1.py` 内置 `ABBREV` 刊名缩写映射表（约 30 条，制造业/控制/材料类刊物）。遇到表外刊名按著录规则查 ISO 4 名录，查到后补进 `ABBREV`，不得手造缩写。

### 7.2 arXiv 最终兜底：abs 页面 meta 标签

curl 请求 arXiv API 仍失败时，抓 `https://arxiv.org/abs/<arxiv_id>` 页面 HTML，以 `citation_*` meta 标签（`citation_title` / `citation_author` / `citation_date` / `citation_arxiv_id`）为权威字段核对：

```bash
curl -s "https://arxiv.org/abs/<arxiv_id>" | grep -oE '<meta name="citation_[^>]+>'
```

### 7.3 接口失效的处置红线

- **AMiner 端点**（`searchtest.aminer.cn/aminer-search/search/publicationV2`，Bearer token 取自环境变量 `AMINER_API_KEY`）失效或持续报错时：**报告用户，勿自创接口**。开放平台旧域名已死，不得臆测新端点或改用未经验证的第三方镜像；改为如实报告哪些条目停留在未验证状态，以 [待验证] 入清单。
- Crossref 限流（429/503）时脚本自带退避，可直接重跑；不得为绕过限流伪造或手写返回数据。
- Semantic Scholar 免费 API 限流较严，查询失败须退避重试并留痕，失败不得记为"查询无果"。
- 修正已验证条目的字段时，只做权威记录可直接支撑的机械修正，逐条写明依据并落盘留痕；存在性存疑的条目（疑似幽灵记录）不下最终结论，标注"待人工定位原始出处"并交用户。
- arXiv 条目元数据版本取决于导入时间——arXiv→正式版切换时 title 必须与权威记录逐字比对，"保留"须有依据。

### 7.4 全文取得与定位（2026-11-04 设立）

服务对象：写作卷 §4.2 的 B／C 级位置。B 级卡在「有没有原文」，不在读。

1. **两处都要查**：本地 `pdfs/`（平铺目录，人工命名）与 Zotero storage（按附件 key 存放）。只扫 `pdfs/` 会漏——曾有一轮盘点因此把本机已有 PDF 的条目标成无全文；其后几批入库又新增多篇。凡引用旧盘点报告的，先确认其为当期。
2. **「有文件」不等于「定位到了」**：题名、作者、DOI 对不上的按「未定位」处理，不得凭文件名近似认定同一篇。病例：自动候选文件名相近但实为另一篇，按近似认定会直接污染证据等级。
3. **三分类回执**，交写作卷：甲＝本机已有可读全文（给文件路径＋页数）／乙＝有元数据无附件／丙＝两者皆无。乙丙须给获取渠道（出版方、作者、馆际、开放版本），不得默认「取不到」。
4. **下载不等于认定**：拿到文件仍须 DOI 或首页比对确认同一篇，确认结果写入回执。

## 8. 文献变更鉴别（台账 diff）

触发：引用集发生任何变动——写作补采、用户手动增删、Zotero 刷新、返工引入。

1. 提取当前参考文献表，空白/断行归一化；
2. 按「第一作者+题名+年份」与 `bib/verified.md` 比对：命中者只读（不重验、不改字段），未命中列为新增候选；
3. 数量熔断：不匹配数与用户申报数明显偏离时停下报告，禁止自行处置——老条目匹配失败可能意味着元数据已被改动，本身即是问题；
4. 新增候选逐篇走 §7 脚本验证，通过后追加台账顺延编号；
5. 双轨规则：正文 [n] 与台账编号独立，靠内容匹配桥接，任何一方禁止重编号；
6. 变更落盘：`reports/` 下出 diff 报告，注明触发来源与日期；
7. 报告类目：新增「计划内变更（授权见 <日期> 会话）」，与新增 / 消失 / 休眠三类熔断情形并列。

## 10. Zotero 直写通道与收口纪律

1. **事实修正**：Zotero 10+ 本地 API 已支持写入（运行时授权本地 key，前置校验同 Web API）；旧版本仍只读。一个会话内通道选定后不中途切换。
2. **通道纪律**：单条 PATCH/DELETE 成功码 = 204（多对象 POST 才 200+JSON），成功判定一律按 2xx；写入后对象 version 跳至库级版本；preflight 永远 GET 实时 version，禁用缓存值——同一纪律约束断言载荷：expect_* 一律取实时快照，禁止凭记忆书写。写入对账按含端点区间计数；桌面端同步等外部写入表现为无通道事件的版本增量，对账时单列核认。
3. **完整性原则**：变更的完整性以类为单位，不以实例为单位——类型切换必须全字段残留扫描（三态清单不作豁免依据；"模型接受该键"≠"该值合法"，conferencePaper 接受 volume 实证）；bib 类修复必须全表扫描（点修复视为未完成）。回读断言覆盖字段值内容与清空态。
4. **身份锚定**：一切修复与审计按 itemKey/DOI 定位；文档编号是引用顺序的投影，随增删漂移，禁止作定位依据，禁止心算区段偏移。重基线唯一基准 = 刷新后 docx 的"条目↔编号"实际映射，落盘 `reports/numbering_baseline_*.md`；台账与大纲互不为基准，仅作交叉校验。
5. **节奏与转换两层制**：一次收口一次 Refresh；docx→md 转换命令只存在一份（本包 `tools/convert.cmd`）。自动提取落点 = `reports/_raw/` 提取件（机械层，字节忠实）；提纲类文件是投影层（承载基线注记与计划态标注），禁止任何自动流程整文件盲覆——投影层只经基线程序更新。

## 15. 机制：体系条文的演进（2026-11-04 设立，同日加聚合与整体回顾）

管束对象：把 `docs/progress.md` 中**工程与制度类**的新增条目、以及 `reports/` 回执里记录的事故与返工，转化为本卷条文。
设立理由：条文演进机制此前只覆盖写作侧，体系侧靠人记得住、靠回执翻得到，忘了就重复踩坑。

触发：与写作卷 §14 同批运行，或用户单令。
游标：记**已处理至哪个日期**（体系条目按日期顺延，无表格式，按条目日期切分即可）。

1. **取增量**：读进度板中日期晚于游标的条目，外加 `reports/` 中同期的返工/事故回执。**按锚点分段读，禁止整文件读**。
2. **聚合（2026-11-04 增设）**：先按「对象＋动作」聚合再分类——同一对象的连续返工（同一脚本、同一台账、同一次写入）只取**末态**，中间态标注「已被后条替代」、不参与分类。判据：聚合后是否再拆不出两条通用规则。
3. **四分类**：**冲突**（与现行条文相反）／**新增**（本卷未覆盖且有可复用对账判据）／**已有**（条文已覆盖，只补病例）／**非体系**（属学术判断 → 转运 `survey-writing` §14）。
4. **举证**：新增须附事故位置（回执路径＋日期＋当事人表述）；无事故不立条。同一坑第二次出现即强制立条。
5. **整体回顾（2026-11-04 增设；落条前必过）**：落条前对全卷三查，任一不过即停：
   - **同题查重**：本卷别处已有等价对账条 → 只补病例，不立新条。
   - **反题查冲**：别处条文对该情形给出不同做法 → 冲突，进裁决队列（自带红线第 1 条）。
   - **层级查位**：新条的**判据**属哪一层就落哪层——数据搬运、编号、脚本、落盘各有归属，判据写串层即为错置。
   另记「缺口清单」：该条生效后同层留下的空洞，入日志，**不当场补条**。
6. **落条**：优先修已有条（§6A／§7／§8／§10 内部），确无归属才另立；同步更新版本行。
7. **记账**：更新演进日志游标；进度板记一条，注明批次、覆盖条目、落点条文号、待复验项与待裁决项。写入须按锚点定位、写完自检，**不手改、不整文件重写**。

自带红线：
- **冲突分两级**（同 `survey-writing` §14，口径一致）：**机械冲突**（同一事实两处说法不一：路径、编号、字段、引用失效）直接改、留病例；**判据／层级冲突**（两处对同一对账问题给出不同做法，或与卷界相抵）**停，报用户裁决**。报法固定四项：新条原文｜旧条原文＋位置｜冲突点一句话｜两个改法与各自代价。裁决前非冲突项可先落，冲突项挂日志「待裁决」。
- **单批超过 5 条先出清单交用户裁决**。
- 本卷条文只写「对账怎么对」，不写「话怎么说」——后者一律转运。
- **体量闸门**：本文件超过 20000 字符时，新增条文前须先拆分（细则与病例移 `references/`，本文件只留判据与指针）。

## 16. 每日文献 Alert 监控（2026-11-04 设立）

管束对象：数据库保存检索／期刊 Alert 的**日常增量**。目标是「有新文献才出声，没新增就安静」，不是把日报当台账。

### 16.1 定位与边界

- 本模块只做**分诊**：拉信、解析、补 DOI/摘要、与台账/正文/历史简报对重、给相关性/优先级/证据上限，输出候选简报。
- **不写 `bib/verified.md`，不改正文，不宣称某文已纳入。** 纳入仍走 §7／§8 的全文核实与台账流程。
- 理由：Alert 邮件最多 C 级，补全摘要最多 B 级；让日报直接入账，等于把未经全文核实的条目混进台账。

### 16.2 初始化与配置

1. 在综述项目根目录跑 `python <skill>/scripts/daily/init_daily.py --workdir ./daily`。
   它建目录、复制脚本、从模板生成 `config.json` 与 `daily/CLAUDE.md`、写 `.gitignore`。
2. `config.json` 填 IMAP 地址、完整邮箱地址、**客户端授权码**、Alert 发件人与域名；
   `ledger_path` 与 `manuscript_globs` 可留空，默认到上一级找 `bib/verified.md`、
   `manuscript/*.md`、`docs/*.md`。
3. 填完先跑 `python check_config.py`；可加 `--test-imap` 实际登录一次，确认授权码可用。
   它只报字段名与格式，不显示授权码。退出码 2＝还没填好，3＝IMAP 登录失败。
4. **授权码等同邮箱密码**：只存在本机 `config.json`，`.gitignore` 必须排除；不得贴进聊天、
   issue、commit。
5. `daily/CLAUDE.md` 是分诊口径，必须按项目填写综述范围、纳入／排除判据、引用角色。
   模板按原 `mail_daily/CLAUDE.md` 的结构脱敏，保留输入优先级、核心/组件/邻域三类、
   硬门槛、五分钟三问、四处去重与空简报纪律；只把项目专属的表号、计数、文件名、
   截止日换成【待填】。四条硬纪律不得删：证据上限、`probable` DOI 待核、覆盖缺口声明、只分诊不入账。

### 16.3 脚本与调用顺序

| 顺序 | 脚本 | 作用 | 退出码约定 |
|---|---|---|---|
| 0 | `scripts/daily/check_config.py` | 只读配置体检；可选 `--test-imap` 登录测试，不显示授权码 | 2 配置未填好；3 IMAP 登录失败 |
| 1 | `scripts/daily/pull_mail.py` | IMAP `UID SEARCH`＋`UID FETCH` 拉 Alert，按 Message-ID 去重，只读不改邮箱状态 | 2 配置/授权码未填；3 取正文失败，邮件留邮箱 |
| 2 | `scripts/daily/parse_alerts.py` | quoted-printable HTML → `_parsed.md`，保留题名、入藏号、覆盖信息 | 4 本轮 0 条（空提醒） |
| 3 | `scripts/daily/enrich_crossref.py` | 题名→DOI→著录/摘要；Crossref 缺摘要用 OpenAlex；与台账、正文、历史简报对重 | 2 全部查询失败（断网），退回 `_parsed.md` |
| 4 | `daily/CLAUDE.md` + `claude -p` | 逐条分诊，写 `brief/YYYY-MM-DD.md` | 非 0 则不归档，邮件留待重试 |
| 5 | `scripts/daily/run_daily.ps1` / `.sh` | 串起 1–4，处理空提醒与归档 | — |

- 脚本来源：核心脚本直接复制自原 `mail_daily` 工作版，不是替代实现；逐项复制关系与改动见
  `scripts/daily/SOURCE.md`。`parse_alerts.py` 逐字节相同，其余只改配置路径与解释器定位。
  真实 `config.json`、历史邮件、简报与去重台账未随包分发。
- Windows 用任务计划程序调 `run_daily.ps1`；macOS/Linux 用 cron 调 `run_daily.sh`。
- 自动化调用 Claude 时**只给 Read / Write / Glob / Grep**，不给 Bash、不给联网；改调度脚本时保留此限制。
- `run_daily.ps1` 必须 UTF-8 带 BOM + CRLF；`init_daily.py` 复制的版本已处理。
- 诊断只读：`check_alert_links.py [邮件路径]`、`uid_gaps.py --folder INBOX`。

### 16.4 分诊结论与交接

简报每条至少写：题名、DOI（`probable` 写「候选 DOI，待核」）、著录、类型、三问结论、
证据上限、与本综述的具体关系、建议动作、待核项。

要把候选推进为正式引用，按 `skills/_shared/handoff.md`：

1. 写作卷先定论断强度（写作卷 §2）；
2. 体系卷取全文、核著录、入台账、给编号与 A/B/C 等级；
3. 写作卷按等级与限定词落笔。

跳过第 2 步直接把简报里的文献写进正文，等于用 C 级证据撑论断。

### 16.5 已知坑

- Alert 邮件常只展示前 5 条；其余题名粘到 `manual/extra_titles.txt`，简报必须声明覆盖缺口。
- `probable`（0.90–0.97）DOI 只能写待核；不得用于断定「已引」。
- 换数据库（Scopus／PubMed／期刊 Alert）时邮件模板不同，先看样本邮件再改解析正则，不要盲跑。
- 手机端删信会造成邮箱 UID 空洞；拉信必须走 UID，不能退回序列号。
