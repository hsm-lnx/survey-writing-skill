## 0. 元规则：规则准入门槛

新条文只能由已确诊病例逼出（附病例位置），禁止理论推演式预设；每条规则带正面样例一处；规则自检先于全稿扫描，miss 先修条文；规则数量增长本身列入版本评审。条文按管束粒度分层：句面（§1）→段级（§12）/段内（§12A）→段间（§5）/章级（§12B）→全文（§9/§11）；新增条文须声明落入哪层，已有层能修就不另立新层。

## 1. 段落与语言形式

- 单句不成段。
- 每段有一个可归纳的论述指向，并有支撑扩展句。中心句位置自由，可在段首、段中或段尾。检验标准：能用一句话概括本段主张，且各扩展句均服务于该主张。
- 允许归纳式段落（先摆证据后下结论），禁止的是无论述指向的文献罗列段。
- 不用破折号、箭头、加号、波浪号等符号表达逻辑关系，一律改用精确的连接词（导致、归因于、与……存在竞争关系、该效应随……减弱等）。
- 正文不滥用加粗与强调符号，加粗仅限标题层级。
- **括注三分**（2026-11-03）：术语对照括注可留（如「回合（episode）」）；导航括注（见第 5 章、见表 1）能删则删，删后读者仍能读懂的一律删；其中「定义见 X 节」一律视为工作稿写法，不得入正文。摘要不放任何指针；正文段内表指针一段一处为宜。专业小众词与本文自定概念按术语对照类处理。

## 2. 论断与引文的匹配

引文义务随论断强度递增：

| 强度 | 论断类型 | 引文要求 |
|------|---------|---------|
| 弱 | 背景陈述、领域共识 | 1 篇可查证文献即可，优先综述，不强求权威但须可辩护 |
| 中 | 状态陈述（主流、常用、代表性） | 2~3 篇支撑限定词 |
| 强 | 比较陈述、机理陈述 | 直接文献，证据须覆盖比较双方 |
| 最高 | 量化陈述（含数字、参数、牌号） | 数字逐字对应原文，交付时列入引用明细表（§6.3），依据等级如实标注 |

- 三种高危形态，写作时自检：全称量化（"所有研究表明"）须改为如实限定且不回避已知反例；文献只报道相关性时不得升格为因果；文献结论的材料体系与工况范围必须随转述保留，不得外推。
- 可辩护性标准：每条引文应能回答"为什么引这篇"，依据为被引量、发表年份、与论断的直接相关性。AMiner 检索时顺带记录前两项。
- 风险分层：弱论断配普通文献可放行；强论断配孤证或低被引文献属高风险，须补证或弱化论断。
- 作者的比较、评价、归纳是综述的原创贡献，不强行挂引文；整段皆为转述而无作者论断的，判定为罗列段，退回重写。
- 证据分级补充：出版方官网的摘要页只决定**著录来源**等级，不决定内容等级；内容等级见 §4.2。`10.5555/*` 为 ACM 内部标识，不得写作 DOI。

## 3. 数字类陈述

- 转述数字：数值、单位、有效数字与原文一致，不做意思层面的变通；用于比较论断的数字不得舍入。
- 数字的用法（置于哪句、与什么对照、支撑哪个论断）服从综述行文逻辑。
- 推算或聚合数字（如由文献数据估算的训练时长）：原文并无该数，必须显式标注推导来源与假设，不得伪称文献报告值。
- **自有计数投影**。管束对象：本综述自产统计数字（"N 例中 M 例"、图谱图计数、汇总比例）。规则：(a) 注明计算来源与基准（"由表 X / 表 S1〈版本/日期〉重算"）；(b) 基准表变更触发重算，禁沿用旧值（并入 §9 触发 a/b 机制）；(c) 承载此类数字的图，图注带样本框声明，不以百分比表述覆盖面。病例：风险登记册曾把图注中的误读占比写成覆盖面结论，未经基准重算；正面样例：以"三点均限已核实 N 案例"限定统计口径的写法。层：段级（§3 组）。

## 4. 文献验证（最高优先级）

两道独立工序，缺一不可：

1. **著录核验**：作者、年份、期刊、标题逐项与权威库检索结果核对。不确定者标 [待验证] 并单独列清单，绝不冒充已核实。禁止编造 DOI、卷号、页码。批量执行细则与脚本见 `survey-ops` §7。
2. **忠实性核对**：文献存在不等于它说了所转述的内容。按 §4.2 三级三动作执行；最终核对义务在作者，相关条目列入 [转述核对] 清单。

- 年份在未来、卷期页码齐全但检索无果、作者与领域明显错位，均为高风险信号，一律标 [待验证]。
- 每条引文在 `bib/verified.md` 台账建立条目，记录被引量、期刊、年份。

### 4.1 覆盖核对：阴性结论与区间引用

管束对象：核对"正文是否真引了文献表每一条"这类**阴性结论**（未引／缺引／未落文）。阴性结论是唯一一类"扫描器不吭声就能得出"的判断，故另立三条：

1. **阴性不出门**。凡"未引／缺失／未落文"结论，须回读被指位置的原句、把原句抄进报告，方可写成结论；拿不到原句只记「待核」，不得写成既成事实，更不得据此升格为规则违规。病例（匿名）：逐号 token 扫描报两条编号"正文未引"，实为一段区间引用所覆盖；所附"证据行号"取自表格单元格而非正文句；该结论曾写进四份记录，回读原句后当日全部撤回重写。
2. **区间当全集读**。`\[a\]--\[b\]`（含 `-`、`–`、`—` 变体）等于引用 a~b 全部，任何计数与多重集比较前先展开。正面样例：`survey-ops/scripts/cite_coverage.py` 对某稿得 token 与实体分开计数、区间展开后全覆盖、括号形态异常 0，退出码 0。
3. **数要可复算、口径要声明**。写进交付记录的 token／实体／覆盖数必须由带断言的脚本产出（不一致即失败），禁止手抄或口算；须声明口径是「正文区」还是「全文含文献表自身编号」。病例：曾长期沿用「全文计数且含文献表自身编号」的 token 数当正文覆盖证据，照不出覆盖问题。技术前提：正文可能含 `γ∈\[0,1)` 这类转义开括号未闭合形态，`\[…\]` 裸配对扫描会吞掉同段真实引用，故覆盖扫描须带括号形态白名单（`cite_coverage.py` 已实现）。

层：文献验证（§4 组）。

### 4.2 忠实性核对：三级三动作（2026-11-04 设立）

管束对象：§4 第 2 点所称的忠实性核对——判断「这条引文是否真支撑这句话」。它不判断文献是否存在（那是著录核验，在 `survey-ops` §7），只判断**转述与原文是否相符**。

**单位是位置，不是文献。** 判级对象是正文里每一次具体使用；同一文献在不同位置可以不同级。文献条目本身没有等级，用途才有等级。

| 等级 | 现状 | 动作 | 完成标志 |
|---|---|---|---|
| A | 已对照本地原文核实过该位置 | **不重核**，只做失效检查 | 转述未改 → 维持 A；转述改过 → 降 B |
| B | 只有摘要或出版方页面 | **先取全文，再核关键句** | 摘到原文关键句并入证据行 → 升 A |
| C | 只有题名或书目 | **先补证，谈不上核对** | 取到摘要 → 转 B；取不到 → 不得独立承担论断 |

1. **A 级做失效检查，不做重读。** 该位置的转述若发生下列任一变动，A 级自动失效降为 B，须重新核对：论断强度升格（弱→中→强）、限定词被删（材料体系、工况范围、相关非因果）、所指命题换成原文另一侧面。只改措辞而命题不变的，维持 A。
2. **B 级先取后核。** 缺全文交 `survey-ops` §7.4（本地 `pdfs/` 与 Zotero storage 两处都要查，只扫一处会漏）。取到后比对**支撑该句的那段原文**，摘录关键句进证据行；取不到则维持 B，且该位置不得写成中／强论断（§2 风险分层）。
3. **C 级先补证。** C 级不是「核对未通过」，是「还没有可核的东西」。取到摘要转 B，取到全文走第 2 条；都取不到则该位置不得独立承担论断，须与 A 级并列出现或改为弱论断。
4. **证据行是唯一产出**：

   | 正文位置 | 论断原文 | 强度 | 原文关键句 | 原等级 → 新等级 |
   |---|---|---|---|---|

   核对结论不落成这一行，视为未核对。§4.1「阴性不出门」同样适用：判「原文不支持」时须抄出原文。
   **落行后跑校验**（`survey-ops/scripts/faithfulness_check.py`）：

   ```
   python faithfulness_check.py <证据表.md> -c <manuscript.md>
   ```

   校验器机械判五件事：表结构五列；强度与等级枚举；B／C 不得承担强／最高论断（「中」须共引 ≥2 篇）；升 A 须摘原文；论断原文须在正文中逐字找到（找不到即正文已改，该位置等级失效）。**exit 0 才可交付**。
5. **不许以文献权威代替核对。** 出版方官网只决定著录来源等级，不决定内容等级；本地无全文就是 B，不因出版方权威升 A。病例：某条文献在出版方页面可查到摘要与全文入口，但本地无文件，仍按 B 计。
6. **不批量承诺。** 「全部核完」不是可交付结论，交付的是证据行；未核的列清单，不得以「已抽查」概括。

层：文献验证（§4 组）。

## 5. 转述与论述结构的关系

- 先立论断链，再分配文献：写段前列出推理链条，再为每个论断匹配证据，禁止先攒文献再编论点。
- 转述按本章论述需要取用文献侧面：同一文献在不同章节可转述不同内容，转述不得与本章论述线索冲突。
- 删引测试：删掉某条引文本段论述不受损的，删除。§11.5 删概念测试与 §13 E7 删句测试同构，判据都是「拿掉它，本段的论断、证据与边界是否受损」。
- 并引多篇时，各文献须独立或共同构成证据群，不得凑数。

## 6. 工作流

1. 收到章节总纲，先列段落提纲（每段一句论述指向 + 拟引用的台账编号，需新增文献的注明）交用户确认，确认后动笔。
2. 写作中每个引用先查 `bib/verified.md` 已有条目；新增条目按证据分层验证（有 DOI 走 Crossref，中文刊 / 无 DOI 老文献走 AMiner 或出版方页面），通过后追加进台账并从当前最大号顺延编号（台账操作细则见 `survey-ops` §8），同步把引用明细表（定义见第 3 条）中该条 ⚠️ 改为已验证编号。
3. 初稿先做删引测试（抽掉引用后论断是否仍成立，装饰性引用当场重写该句），随正文交付一张「引用明细表」，每行四列：

   | 字段 | 填写规则 |
   |------|---------|
   | 占位符【作者 年份】 | 与正文占位一一对应 |
   | 台账编号 | 未入库标 ⚠️待验证，验证后补号 |
   | 支撑点 | 注明正文第几段哪句转述或数字由该条支撑 |
   | 依据等级 | A=已对照本地原文 PDF；B=仅凭摘要转述；C=仅凭书目元数据推断 |

   交付时正文在前、明细表随后；C 级行汇总数报给用户。
4. 修改任务先指出原文问题再给修改稿，不直接重写。
5. 全文完成后执行"强论断配弱文献"错配扫描，输出风险清单。
6. 每节完成判定：明细表交付 + C 级数经用户确认 + 忠实性抽查（§4.2）通过；交付时声明本稿对 `docs/claims.md` 各论断的影响（强化/弱化/无涉）。

## 9. 变更传播与返工

状态文件：`docs/progress.md`（节状态板）、`docs/claims.md`（关键论断登记）。

触发（任一即启动）：a. 台账条目被修正或删除；b. 某节写作/修订强化、弱化或推翻 claims 论断；c. 结构调整（章节增删、重排）。

1. 冲击扫描：按 claims 定位论断的全部声明位置，按引文定位受影响条目的全部引用节，输出返工清单（节+段落+原因）交用户分诊：立即改 / 排队 / 明确不动（记录理由）；
2. 返工执行走 §6.4：先指问题 → 范围声明 → 只动范围内 → 被动段落重做删引测试（§5）与明细表（§6.3）；
3. 闭环：progress 版本号+1，claims 同步修正。
4. **结构操作纪律：搬运双清点**（管束对象＝章节搬运、段落迁移、删减，触发 c 的执行细则）：搬运以段 id 为单元，批末双向清点（来源节−x 段/目标节+x 段/全文段 id 总数不变），diff 落盘；总数对不上即熔断，禁静默（同 §8.3）。
5. **搬运与改写分离**：搬运批只移动不润色；发现带病记入体检清单另批处理（与 §13"禁止同句两改"同源）。
6. **依赖复检**：迁移/删减后复检三项——概念首现义务（§11.2，首次定义位置可能已随搬运改变，concepts 同步更新）、章级角色（B1）、引述锚定（H4）。
7. **删减三步**：隔离（被删段连同明细表行先转补材候选，不直接销毁）→对账（删后跑 §8 diff，"引用集零增删"以 diff 验证，不以声明为准）→回填（候选清单登记 progress）。

   结构操作纪律（4~7）病例：压缩轮曾误删证据、交叉引用错位、两次编号重排漂移；正面样例：收束轮编号终排（一次重排＋清单核验）。层：全文（随 §9）。

## 11. 概念纪律

管束对象：概念的引入顺序、定义位置、规范命名与回收复用。诊断：§1 管段内、§5 管段间论证链，均不产生跨段概念义务，导致"每段各自成立、全文读不通"。

1. 概念台账：写作启动时建立 `docs/concepts.md`（与 claims 同级），逐概念登记：规范名｜禁用别名｜首次定义位置｜状态（待引入/已定义/沿用）｜复用章节｜**全文分布与详略级差**（哪几节展开、哪几节一句带过）。规范名全局唯一，正文禁止同义漂移。
   - **台账是概念一致性的唯一抓手**：一致性靠「认准台账里的说法＋台账盯全文分布与详略」，不靠行内「详见 X 节」的互相指认——指针只能说明位置，说明不了说法是否一致。
2. 首现三选一（管束对象＝本文自定概念与专业小众词；国际通用术语不在此列）：当句或邻句必须满足其一：(a) 一句话定义；(b) 行文指认已定义位置（"如第 2 章所定义的…"）；(c) 标注来源（"即文献[X]所称的…"）。三不满足，该句退回重写。
   - **标准术语裸用**：benchmark、baseline、episode 等国际通用术语直接使用，不触发首现义务，不为「显得规范」而加原词括注。负面样例：`基准（benchmark）`→`基准`。
   - **(b) 只许回指，不得向前指**：(b) 只承认**回指已经定义过**的位置；括号式指针 `（定义见 X 节）` 在括号处拿不到信息，属工作稿写法，一律删，指认须走行文句子。负面样例：`训练环境（定义见 3.2 节）`→`训练环境`。同样不得用「详见第 X 章」「后文将展开」「正式判据见 X 节」一类指向**尚未展开**的后文来充当首现义务。**前文定义只要与后文不冲突即可自足**——判据是「读到这里的人此刻够不够用」，不是「后文在哪」；一致性由 `docs/concepts.md` 台账管（§11.1），不由行内指针管。
   - **过度定义与过度阐释同属违规**：后文要对某概念正式详述的，前文只给够用的工作定义，不提前把后文的分类轴、类目清单、判据细则搬过来（§11.8）。目的是前后自然衔接、读起来没有不适感，不是「前文把话说全」。
3. 概念依赖前置：§6.1 段落提纲每段增加两列——引入概念/依赖概念。依赖概念必须是前文已引入项；依赖项在后方段落才引入属提纲错误，动笔前修正。
4. 节级框架句：每节首段给出本节概念坐标：≤5 个承重概念各配一句话定义。坐标服务于本节叙述主线，不是文献综述。
5. 节末闭环扫描：每节完成后对新引入概念逐个执行删概念测试——后文有复用（台账登记位置）则保留；无复用且本节未收束则删除或降级为例示。与 §5 删引测试同构：概念也要回答"为什么留你"。
6. 回收义务：已定义概念后文复用时用规范名回指，禁止重新定义；有意精化的（如从"闭环"精化为"部署观测一致性"）须在台账登记新位置。
7. **台账随正文同步更新**：任何正文改动涉及概念名、定义、首现位置或复用范围，须在同一落文批次内更新 `docs/concepts.md` 的现行台账；回执须列出「概念台账 diff」（新增／改名／精化／删除／位置变更）。未同步者视为该批未完成；禁止「先落文、后补台账」。
8. **定义深度随位置递减**。概念在首次出现处只给够用的工作定义，不提前调用后文的分类轴、类目清单与结论；引言段尤甚。判据：删去定义段中「后文才展开」的任一项，该段是否需整体改写；需要的话，说明它是预告段而非定义段，退回。
   终判据：**前文定义与后文不冲突即可，不要求前文覆盖后文**；合格的定义读起来应与前后文自然衔接、没有不适感。反过来，若一句定义必须靠「详见第 X 章」才成立，那不是定义，是指针——退回重写。
   负面样例：引言曾一并列出后文才展开的形态分类与反馈来源分组，属透支；正面样例：精简为引言级工作定义——只给交互对象与接口，形态只给一句 gloss，分类归后文。层：概念（§11 组）。
9. **分类须过「判据＋必要性」双闸门（2026-11-05 增补）**。对研究对象、任务或方法分组时同时检查：(a) 类别须由对象本身可核对的属性或决策结构区分，不得由算法名、表示形式或环境形态反推；「某方法可用于某类问题」不等于采用该方法的案例就属于该类。(b) 每一类须有证据，并在后文承担比较、解释或组织功能；只为形式对称造出的子类、仅在一段出现且后文不复用的孤立分类，删除或并回上位类。§12A H2 检查「预告轴与实际展开是否同构」，本条先检查「这套分类本身是否成立且值得保留」，二者不互相替代。负面样例：某章曾为形式对称造出两条并列子类，其中一条只有方法综述、一条无本领域案例，且这些子类未在后文复用；正面样例：按动作后果是否跨步区分单步与序列，依据各案例的决策结构核定，不因所用算法名归类。层：概念（§11 组）。

## 12. 承重段五规则与关节扫描

管束对象：段落的中心句、举证方式、结论范围与信息顺序。诊断：段落各自通顺但承重句空转、结论超支、判断被例子淹没。

1. **中心句要经得起一句追问**。段首主张必须具体到能当场回答"凭什么"；"X 很重要 / X 有作用"这类空断言，要么补判据或机理，要么降级为例子铺垫句。
   正面：段首给出可判定的分类判据（"结果所依赖的变化可按来源分为两类"），随即给出分类。
   反面："训练环境的构建与验证是应用中的重要限制"式首句，无判据。
2. **例子进场先报名份**。并列举证时，第一句说清这组例子按什么归堆、彼此差在哪，不许让读者反推。
   正面：按"某方面 / 某方面 / 某方面"逐组报名后再给例证。
   反面：四个例子连排，归堆口径（"其他研究的任务边界有所不同"）迟至例子之后才出现。
3. **结论只花已经放进来的钱**。"因此/据此/综上"只能收拢前文实际写过的内容；结论里冒出前文没有的概念或维度，回上文补，或从结论删。"N 个方面"式预告须与实交条目一一对账。
   正面：结尾"因此"收拢的正是前文已展开的几组证据。
   反面："因此"句冒出前文未铺陈的维度；"三个方面"预告与第三条实交内容不符。
4. **最重要的话先说**。承担转向或裁决的句子（"但……并不证明……"）放段首或紧随中心句，例子永远排在判断后面。
   正面：段首即给出"应按什么维度比较"的裁决。
   反面：关键裁决"通用任务上的算法进展并不直接证明……"埋在例子串与两轮铺垫之后。
5. **强主张自带边界**。断言说到多满，"它不能推出什么/何时失效"就跟到多远；全称式表述（"所有……都……"）默认违规，段内已给成立条件者除外。
   正面：结论后紧跟"不能仅凭……判定其为……""不能直接表述为……"的边界句。
   反面：全称式性能结论无成立条件。

### 12.1 规则自检（先测规则，再信扫描）

对已标注案例跑五规则，判定必须全中；任一 miss 先修规则措辞，自检通过后才进入全稿扫描。规则本身也要过"命题核对"。判定结果与病例存档归 `reports/` 与 `progress.md`，本文件只留条文，不留执行史。

### 12.2 D类·关节扫描

范围：摘要 + 全文各章逐段。每段七问：

① 中心句主张是什么，"凭什么"能否当场回答（规则一）；
② 每个支撑句在干哪种活：机理/实例/证据/边界，四种都不沾的标"迷路句"；
③ 结论句收拢的是否就是上面这些，有无冒新概念（规则三）；
④ 并列举证报名份了吗；"N 个方面"预告与实交对账了吗（规则二/三）；
⑤ 重判断在段落前半吗；强主张带边界了吗（规则四/五）；
⑥ 段内次级中心清单：各干哪种活（分组/划界/递进/转折/限定），连接词与功能匹配吗（H1）；引述跨中心共用时显式说明双重角色了吗（H4）；
⑦ 预告的分类轴与实际展开的分类结构同构吗（H2）；"因此"收拢域与主中心证据域对齐吗（H3）。

产出体检表：位置 / 中心句主张 / 支撑句角色清单 / 次级中心清单(功能+连接词+判定) / 判定(清楚·需修·重写) / 一行病因；病句清单(位置/原句/病型/一行修法)。

体检表只出不改，交用户裁决后按 `survey-ops` §6A 批量作业纪律开卡一次批执行；冻结对象（规范名、引用编号、图表号）按 §6A 第 6 条处理。涉及待引用核对的句子标"待引用核对"，等命题核对结果再动。

## 12A. 段内层次规则（H类）

管束对象：承重段内的多中心结构。诊断：§12 五规则隐含"一段一中心"假设，实际承重段常为主中心→次级中心→支撑引述三层；病灶多在次级中心之间的接口与收拢域，不在句内。五规则判"清楚"的段仍可能有 H 类病灶。本组条文落入元规则分层中的"段内"层。

1. **H1 次级中心进场先报功能**。次级中心相对主中心干哪种活——分组（对象域内归堆）/划界（什么不在对象域）/递进/转折/限定——须句中显式；功能不同的次级中心禁止用"此外/同时/另外"等平行连接词并置。
2. **H2 分类轴同构**。预告的分组维度与实际展开的分类结构必须同构；某维度在预告中是组间差异、例证中却无对应内容，须从预告移出或补例。
3. **H3 收拢域对齐主中心**。"因此"的指称域 = 主中心下的证据域；划界类证据支撑"边界在哪"，不得作为"比较须区分条件"类结论的依据——对域外例子谈"未区分 X 不能比较"是范畴错误。
4. **H4 引述锚定次级中心**。每条引述只服务其所在次级中心；跨中心共用须显式说明双重角色，否则拆引。
5. **H5 伞名与子项一一对应**。用上位词概括一组并列项时，伞名的覆盖范围须与子项集合相符；子项异质（分属不同类）不得强行归入一个伞名，改用并列命名或拆句。判据：把伞名展开，逐项问「它真是这个伞名下的吗」，任一项答否即越界。
   负面样例：拟以「环境构建与验证」概括「构建／验证／数据准备」三项，数据与质量信息既不属构建也不属验证，伞名越界；正面样例：改为并列三类（环境构建、验证、数据准备），与本段成本清单逐项对应。层：段内（§12A 组）。

### 12A.1 规则自检

对已标注病例跑 H1–H5，判定须全中；miss 先修条文，自检通过后才进入全稿七问扫描。

### 12A.2 首次自检

负样本 = 某段在 §12.1 五规则自检中判"清楚"、按 H 类应判"重写"的段落（执行时先存档至 `reports/_raw/` 并记录行号基准）。该段是两层粒度差异的实证，预期病灶三连：

- H1：以划界功能用平行连接词并置（"此外，部分研究的……不在此列"）；
- H2：预告三维度，但三组例证在某维度上无组间差异，该轴实际存在于"三组与另两类研究"之间，预告与例证不同构；
- H3："因此"句对域外例子谈"未区分某条件不能直接比较"，收拢域错位。

正样本 = 按 12A.3 三段制改写后的版本，预期清楚；逐组报名份、接口词规范的段落为 H 类正面样例。

### 12A.3 落文基准（三段制结构模板）

本版不含原文内容，只给结构。落文时按此三段制写，引用编号与限定词零改动：

**第一段·宣告转向**：先承认既有储备（"X、Y、Z 已为……提供了较丰富的算法储备[n]–[m]"）；再指出通用进展不证明本域已具备同等条件，把分歧落到具体环节（"分歧与困难集中在……上"）；最后给出两根轴的总述，让读者知道下文怎么走。

**第二段·轴一**：说明分组判据（"按……可归为三组"），逐组报名份并在组末给出组间差异，收句提示"跨组比较性能数字前须先声明这些条件"。

**第三段·轴二**：给出反例类情形（"环境形态相近并不保证可比"），说明不可直接比较的原因不在某一条件而在任务不同，最后宣告本文分析主线（"本文据此把……作为分析主线，同时保留……的影响"）。

**落文纪律**：替换范围为声明的单段或指定段；落文前核对该段引用编号在现稿中的实际位置，防止落文后重复；核对末段与后续段落的分工，发现内容重复列清单报用户。落文后执行残留扫描＋引用闭合校验＋指纹更新＋台账登记；改写版复检结果回填 12A.2。

## 12B. 段功能定位与公平呈现（B类）

管束对象：段落作为章级论证链节点的外层定位，及评价性论断的呈现义务。诊断：段内层封住后，"本段在全文论证中干什么活"无对应条文；对比评价类论断无单边举证禁令。本组条文落入元规则分层中的"章级"层。

1. **B1（§6.1 增列）段落提纲增"章级角色"列**：本段服务于哪条论证链/哪个子问题，一短语；无角色贡献的段在提纲层删除。段间顺序由论证链决定，不由素材顺序决定。
2. **B2 公平呈现义务**。对比/评价类论断须以对方最强形式呈现后评价，禁止单边举证；批评某环境形态后须给其合理定位或适用条件。
3. **B3 提案定位语态**。管束对象：候选架构、评价工具、建议类章节的首个定位段。规则：该类段落须显式声明证据基座与主张地位——指认归纳来源（哪张表/哪组发现），并声明"属综合建议而非已验证方案"；禁止发明语态（"本文提出/我们设计"）起头，禁止无定位段直接进入方案细节。

**自检样例**：B2 —— 批评某类缺口后给出"该形态适用于……约束下"的合理定位，判清楚；只批评不定位，判须中。B1 —— 对三段制改写段标注章级角色，应得"宣告转向→轴一→轴二并宣告主线"；标注跑不通则修列设计。B3 双向自检 —— 有归纳定位段的提案章判通过（指认归纳来源并声明综合建议，非发明语态起头）；无定位段直接进方案细节判违例。

## 13. 句子层可读性规则（E类）

管束对象：句内句法。诊断：§1 管符号、§12/12A/12B 管论证结构，均不判"读者第一遍能否读通"；结构层判"清楚"的段仍可含病句，且结构改写本身会新造病句（结构对而句法堵）。

- **E1 伪主语与花园幽径**。句首名词串实为定语的（句首名词在谓语中无动作对应），须还原：补定语标记、动词化（如"在X"改"限于X"）、或拆句。检验 = 按主谓宾线性解析一遍，中途需回读者的句子返工。
- **E2 名词化不当**。堆叠式双层压缩（"对A影响B的分析/研究表明"）还原为动词句："分析了A对B的影响，结果表明"；反向同样违规——裸形容词/动词短语作名词成分（"系统集成复杂列为主要挑战"）补足名词化标记（"系统集成的复杂性"）。
- **E3 逻辑算子堆叠**。一句含两个以上否定/排除/限定算子（不、非、仅、除、所有）致读者需做逻辑变形的，改为直陈或单算子。
- **E4 并列与搭配**。并列项共享成分省略不均致歧义的补全；主宾搭配错位的换动词（"汇总案例，包含任务"→"各案例分属任务"）。
- **E5 冗余复述**。同一事实同一细节段内两次完整陈述，留带限定或页码的一处。
- **E6 缺失型病**（与 E1–E5 的冗余/错位型相对：那些是写多了、写歪了，这是该有的没写）。两形态：(a) 缺逻辑主语——判断句主语缺席，发现句与结论句尤甚；(b) 缺具体动作——轻动词（进行/实现/具有/予以/加以）承载抽象名词，换成物理动作。判据 = 按主谓宾解析一遍，主语或动作填不出来即命中。不设机械扫描：句首代词绝大多数为合法回指，机械扫描假阳性率过高，E6 以人读为准。负面样例：发现句以"性能……""验证……"起头缺主语；正面样例：补为"各案例报告的性能指标"与"策略验证"。
- **E7 修辞性冗余句**。为对仗、排比或"显得完整"而写的总结句，删去不损失任何信息。判据 = 删句测试：删掉后本段论断、证据与边界均不受损者即删。与 E5 不同：E5 是重复已有信息，E7 是本来就没有信息。负面样例：段末总结句，作者判"这不像人话，没有这句完全不影响"；正面样例：删后段落由证据清单直接进入归纳，读来更紧。
- **E8 标签化列举惯性（2026-11-05 增补，待复验）**。句子的真实关系是递进、先后或权重不等时，不得用「X 有三：其一／其二／其三」把关系压平成编号清单；改用承担实际动作的谓语与连接词写出关系。只有各项确属并列清单、后文也按同一组项目复用时，冒号与编号才成立。检验 = 删掉序号后，读者能否仅凭谓语和连接词复原项目间关系；不能即命中。负面样例：「分析对象有三：」「全文围绕三问展开：其一……」让标签代替主线与权重；正面拟文：「本文先……再……最后……；三问依次承担范围界定、主体分析与部署边界限定」。

**修法不变量**（两条，违反任一回工）：
a. 概念名守 §11 台账，禁止为顺口丢规范名；
b. 数字、限定词、页码标注不丢，信息量不减。

通用检验：修后默读一遍，无回读。

**自检**：病例集按 E1–E8 判定须全中，修后版本判"通"；miss 先修条文。判定结果与病例存档归 `reports/` 与 `progress.md`，本文件只留条文，不留执行史。

**执行时机**：E 类不设独立窗口——随 D 类七问扫描同步执行（体检表每段增"病句清单"格：位置/原句/病型/一行修法），与结构裁决合并、批改窗口一次执行，禁止同句两改。

**13.6 基础规则复检（落文闸门）**。结构改写基准文案与一切落文执行，须复检 §1 基础形式规则（单句不成段、符号禁令等）；结构层合规不豁免基础层——新层规则的产品不得携带旧层违规。落文执行发现基准文案有基础违规：停下报告，不得沉默复制。"零改动"纪律指引用编号与限定词，不覆盖形式违规。病例：结构改写后某段遗留单句成段，基础层复检当场拦下。

## 14. 机制：案例驱动的条文演进（2026-11-03 设立）

管束对象：把 `docs/progress.md` 中**行文类**的案例记录（写作技巧案例表）与当轮对话中形成的行文判断，转化为本文件的条文。
触发：用户指令「演进 skill」或按批次定期运行。
游标：记四样东西，**下次演进直接复用，不重读全文**：

1. **定位锚**——案例表起点标题与终点标题；
2. **表头**——列序固定，按列位取值，不靠猜；
3. **已处理行数**——累计到第几行；
4. **末行指纹**——末行案例列前 20 字，全表唯一。

另记已判「非行文」的条目，避免重复裁决。

1. **取增量**：按锚点定位案例表，从已处理行之后取新行。**注意落点差异**：案例行插在表格最后一行之后，位置可能在**文件的中段**；文件末尾往往是其他类型记录。因此「翻到文件末尾看有无新内容」在本节不成立，不得据此判定「无新增」，也不得整文件读。若末行指纹在表中命中 0 处或 ≥2 处，停止并报用户裁决——不得改从首行重读（重复吸收），也不得默认「无新增」（漏吸收）。本轮对话中尚未入表的行文判断，先补入表末行再处理。
2. **案例聚合（2026-11-04 增设）**：先按「位置＋决策对象」聚合再分类。同一段落对同一决策的连续迭代只取**末态**，中间态标注「已被后条替代」、不参与分类。判据：聚合后是否**再拆不出两条通用规则**；拆得出就还是两条，拆不出就是一条。理由：同一个段落的五轮磋商若逐行立条，会长出五条近义条文，还会把已被自己推翻的中间态正式记成规则——这是「机械增补」最主要的来源。
3. **四分类**（每行／每聚合组必归一类，不得跳过）：
   - **冲突**——案例与现行条文相反。优先级最高：改条文，不改案例。
   - **新增**——现行条文与该层均未覆盖，且有可复用判据。
   - **已有**——条文已覆盖，只补正/反样例，不立新条。
   - **非行文**——概念命名、分类轴、结构顺序、图表、投稿约束等，归 `concepts.md`／结构批次／投稿清单，不进本文件。**其中属机械运转者（脚本、台账、编号、Zotero、批量作业、落盘对账）不在此止步**：写入演进日志的「体系通道·转运待评估」清单，由 `survey-ops` §15 处理——本卷只负责不误收，不负责丢弃。
4. **举证（§0 门槛）**：新增须附病例位置（行号、快照路径或案例行）+ 正面样例一处；无病例不立条。未落文的病例可立条，但条文与日志双标「待复验」，该段定稿后回核，改法与条文不一致即修条文。
5. **整体回顾（2026-11-04 增设；落条前必过）**：新条不得直接塞进「最像的那一节」。落条前对**全卷**做五查，任一查不过即停在该处，不得以「先落再调」绕过：
   - **同题查重**：同一意思已在别处成条 → 只补病例，不立新条。查的是**意思**，不是关键词；同义表述要按判据比对。
   - **反题查冲**：别处条文对该情形给出**不同做法** → 冲突，进裁决队列（自带红线第 1 条）。
   - **层级查位**：用新条的**判据**（不是例子）定层。例子可跨层，判据不能；判据属句法却落进概念层、属概念却落进段落层，即为层级错置。
   - **完备查缺**：该条生效后，同一层的邻近情形是否留成空洞。是 → 记入日志的「缺口清单」，**不当场补条**（为凑完备而临时立条是第二号机械增补来源）。
   - **体量查衡**：某层是否因该条独大、某节是否因此失去单一主题。触发 → 先考虑并入相邻条或上提为上位表述，再考虑另立。
6. **落条**：优先落在已有层（§0 分层原则），确无归属才另立层；同步更新版本行与修订摘要。
7. **记账**：更新演进日志（批次、覆盖案例行、**新指针**、落点条文号、待复验项、**待裁决项**、缺口清单）；状态板记一条批次行。写入须按锚点定位、写完自检，**不手改、不整文件重写**。

自带红线：
- **冲突分两级，改与不改不由执行者自定**：
  - **机械冲突**——同一事实两处说法不一：笔误、路径、编号、术语别名、引用失效。直接改，留病例，不打断批次。
  - **判据冲突／层级冲突**——两处对同一问题给出**不同做法**；或新条与卷界、路由、分层原则相抵。**停，报用户裁决**。未裁决前不改条文，但**必须报**，不得搁置不报、也不得自行择一。
  - 报法固定四项，缺一即视为未报：**新条原文｜旧条原文＋位置｜冲突点一句话｜两个改法与各自代价**。禁止只说「有冲突」不给选项。
  - 裁决前，同批非冲突项可先落；冲突项挂日志「待裁决」，下批先处理待裁决项。
- 禁止为维持版本稳定而保留矛盾条文；但同样禁止以「必须改写」为名先斩后奏：机械冲突可自行改，判据冲突必须过裁决。
- 单批条文增量超过 5 条，先出清单交用户裁决，不直接落文（§0「规则数量增长列入版本评审」）。
- **只改装不装内容**：演进批只改条文，不得顺手改正文；正文改动另开批次。
- **读取经济**：本机制的读取范围限于案例表与游标，不读落文批、不读工程记录。
- **体量闸门**：本文件超过 20000 字符时，新增条文前须先拆分（细则与病例移 `references/`，本文件只留判据与指针），否则后续条文会被中段遗忘稀释。
