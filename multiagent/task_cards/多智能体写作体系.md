## 〇、拓扑与硬约束

TRAE 官方机制（`docs.trae.cn/ide/agent`）：

- 自定义智能体：AI 输入框 `@` → 面板底部「创建智能体」；
- 勾「可被其他智能体调用」须填 **英文标识名** 与 **何时调用**；
- **只有内置智能体 "Agent" 能调用自定义智能体**，自定义之间不能互调；
- 被调用时 **独立上下文**（它拿不到你们在主对话里说过的话，只拿得到提示词和传给它的文件）。

拓扑为星形，主控坐内置 Agent：

```
                  ┌───────────────────────┐
                  │ 主控／法官（内置 Agent） │  ← 唯一能改主意的地方
                  └───┬───────┬───────┬───┘
            ┌─────────┘       │       └─────────┐
            ▼                 ▼                 ▼
      cold-reader       paper-reviewer      drafter
       （冷读）            （挑刺）           （执笔）
       只开「阅读」        只开「阅读」        全工具
                          │
                    ledger-auditor（对账，阅读）
```

三条由此推出：

1. **法官只能是主控或你本人**。执笔不自裁，读者不建议，审稿人不改字。
2. **席位之间靠文件传参**，不靠对话——独立上下文意味着对话里说过的它拿不到。
3. **工具即权限**。读者席与审稿席只勾「阅读」，物理上改不了稿；对账席也建议只勾「阅读」，命令由主控跑、结果落盘给它读。

## 一、五个席位（含频次）

| 席  | 名称        | 英文标识名（可改）    | 工具              | 频次              | 产出                     |
| -- | --------- | -------------- | --------------- | --------------- | ---------------------- |
| 读者 | 冷读者       | `cold-reader`  | 只「阅读」           | 每轮              | `reader.md` 回味＋读感＋悬置账  |
| 审稿 | 审稿人       | `paper-reviewer` | 只「阅读」           | 每 2–3 轮／结构轮／投稿前 | `reviewer.md` 主张—凭据裁定表 |
| 对账 | 对账员       | `ledger-auditor` | 只「阅读」           | 每轮              | `audit.md` 差异表         |
| 法官 | 主控        | —              | 全               | 每轮              | `verdict.md` 裁决表       |
| 执笔 | 执笔        | `drafter`      | 阅读＋编辑＋终端        | 按裁决             | 改后正文＋回执                |

各席的 **「何时调用」填法与「工具／MCP 勾选」见 §九**——那里决定主控会不会误派、以及"工具即权限"成不成立。

### 1.2 定位卡

**冷读席**｜报告一段文本在一个初次阅读的人身上发生了什么。
- 唯一判据：我的阅读状态（悬／合／绊／记得）。不是"文本对不对"。
- 只读正文一份；只出回味、读感、悬置账、未合上、语病。
- 不碰：规则可判的事（格式、账目、编号、表结构）、"主张撑不撑得住"、改法。
- 分界句：**照规则一查就知道的，不归它；读过去才知道的，归它。**

**对账席**｜报告文本与它自己声称的数字、结构、台账对不对得上。
- 唯一判据：实测 vs 应有（应有来自台账、冻结快照、题注清单、脚本口径）。
- 只读正文、台账、冻结快照、已落盘的原始输出；只出差异表。
- 不碰：读感、学术判断、修改。**也不碰"验修法"**——要不要这么修是决定，不是对账。原始命令由主控跑并落盘给它读。
- 分界句：**它答"对不对得上"，不答"该怎么改"。**

**审稿席**｜判断最强的主张有没有凭据。
- 唯一判据：稿内写出的凭据（表、数、引文、案例），不是领域常识。
- 只读正文；只出主张—凭据裁定表与必答问题。
- 不碰：文字、格式、账目。
- 分界句：**冷读问"读起来怎样"，审稿问"凭什么"。**

**法官（主控）**｜把两三份报告变成一份可执行裁决，并定本轮预算。
- 唯一判据：两卷条文、`docs/claims.md`、以及"删了读者会失去什么"。
- 只出裁决表；**不落字**。
- 分界句：**法官定"改什么"，执笔定"怎么写"，法官复核"改成了什么"。**

**执笔**｜把裁决表变成 diff。
- 唯一判据：裁决表写的范围。
- 只出改后正文与回执；不判断改什么、不扩范围、不自创改法。
- 分界句：**它只管"落成什么样"，不管"该不该"。**

### 1.3 为什么没有常设编辑席

编辑判的是"收不收"，需要成品。稿子还是中文草稿、图未绘时，编辑席只会返回"语言不可读、图表不合规、篇幅超限"——这些全是账，不是判断，对账席第六项已盖住。真正的缺口是"信不信"，那是审稿人席的活。编辑席只在 §五 的两个节点以问诊形式使用。

## 二、提示词与法官规程

### 2.1–2.5 各席提示词

> **提示词正典在 `mas_agent_prompts.md`，本节不复制**。改提示词只改那一份，避免三处并存后分叉。

对账席注意：对账是**八项**（含「概念首现扫描」），第八项专管"术语先用后定义"——它照 `docs/concepts.md` 一查就知道，不该占冷读的条目。

### 2.4 主控／法官（内置 Agent）

> **本节是法官规程的正典**；`mas_agent_prompts.md` §五 只是每轮开工的三句模板（指回本节）。

```
你是本轮主控，也是唯一法官。你不写正文。

输入：reader.md、reviewer.md、audit.md。
开工第一件事读 docs/task_cards/mas_pending.md：用户已裁决的条目转成本轮候选（进裁决表"改"）；
标「滞」且仍未决的，不许再以"转用户"结案，只能升级或当场给建议。

一、分流
- audit 条目：只判"是不是真对不上账"。是→必改；判不了→标「转用户」。不许自行放宽。
- reviewer 条目（本轮未跑审稿时此栏为空，须在裁决表里写明"本轮未跑审稿"及原因）：
  只判"本稿能不能答"。能答→进结构队列或判改；确实成立但本稿答不了→标「已知缺口」，
  写进回执的"未改并上报"。
- reader 的四块，分三种用法：
  ·【一】节读感与超载：不作条目，作证据。某一节标"卡"或"超载"，本轮优先看这一节，不逐条改字。
  ·【二】悬置账：不出裁决。它是读的轨迹，不是缺陷清单。只有两列可转为条目——
    「早说啊」可立"回收太迟"一条（改法通常是前移或删一句），「自解·没台阶」可立"缺台阶"一条。
    「原来如此」「自解·有台阶」一律不立条——那是作者安排对了。
  ·【三】【四】：逐条进第二步。

二、五码裁决（只对 reader【三】【四】）
改｜不改-条文（引写作卷具体条）｜不改-论断（引 docs/claims.md 行）｜进结构队列｜转对账
「不改」只许用面向读者的理由：条文、已登记论断、或"删了读者会失去 X"。
不许用项目历史当理由（"这是上次定的""用户要求过"）。写不出来，就判「改」或「转用户」。

三、合并
同一病灶出现三次以上，停止逐条判，改立一条结构级条目。
合并判据是"同一论断／同一关系"，不是"同一症状类型"。

四、定预算（写在裁决表表头）
授权单位：段（默认）／节（结构轮）／章（须用户当场批准）
体量：措辞 ≤20 处，结构 ≤2 处；超出进队列并写明本轮目标
结构轮与措辞轮分开跑，不许一轮既动结构又动措辞。

五、收工
备份齐、四项核验过（diff 行／引用多重集／pandoc 解表数／SHA 与字节）、回执落盘。

六、三本账（缺一即本批未完成）
① docs/task_cards/mas_pending.md：新条目编号追加、已决改状态、连续两轮未决标「滞」；
② docs/freeze_register.md：用户本轮若下冻结／重开／解冻令，改表并追一行变更记录，
   与落文同批（项目没有该文件时，把本轮冻结范围写进 verdict 表头）；
③ docs/progress.md：按主要动作归区记一条（一条不拆两区），按项目约定的通道写，写完跑检查。
④ 跑闸门：python scripts/mas_gate.py <本轮目录>，须全部 PASS 才能收工。
   它机械判五件事：reader.md 三块在不在、audit.md 八项齐不齐、verdict 写没写授权单位与体量、
   U 账 mtime 晚不晚于 verdict、有结构条目时有没有 reviewer.md。**这些都不是提醒，是关卡。**

七、停止
见 §三「停止规则」；另设清账闸——U 账标「滞」达 5 条时停开新轮，先由用户一次性裁决。

输出：reports/_raw/mas/r<N>_<date>/verdict.md
```

## 三、一轮怎么跑

```
⓪ 结账    主控读 mas_pending.md：用户已裁的转本轮候选，标「滞」的升级。
① 冷读    @cold-reader      → reader.md（只给正文一份，不给台账、纲要、往轮裁决）
② 对账    @ledger-auditor   → audit.md（原始命令由主控先跑、落 raw_*.txt，对账只读）
③ 挑刺    @paper-reviewer   → reviewer.md（结构轮前必跑、投稿前必跑；其余每 2–3 轮）
④ 裁决    主控自己           → verdict.md（表头写死授权单位与体量）
⑤ 执行    @drafter          → 改后正文 + 回执
⑥ 复核    四项核验 + progress check + 三本账（U账／冻结台账／progress）+ 跑闸门
          python scripts/mas_gate.py reports/_raw/mas/r<N>_<date>
          有 FAIL 不得收工
⑦ 停/续   满足停止规则即收轮；U账「滞」≥5 条时停开新轮，先清账
```

**停止规则**（缺了它冷读可以永远读下去）：
连续两轮同类型新条目为 0；或本轮与前两轮重复率 ≥70%；或本轮「改」≤2 且无结构级条目。任一成立即收轮。

**清账闸**：U 账标「滞」的条目达 5 条时，**停开新轮**——先由用户一次性裁决。
理由：沉淀不决的条目会让每一轮都在同一批陈账上打转，措辞轮反复改的其实是同一批位置。

## 四、三个保险点

1. **工具即权限**：读者席、审稿席只勾「阅读」，物理上改不了稿。
2. **判定表留痕**：每条「不改」挂条文或 claims 行，verdict.md 就是这一轮的账。翻案翻账，不翻记忆。
3. **回滚粒度**：文件层备份能还原文件，还原不了判断。verdict.md 让判断也有记录，改坏了可按条回退。

## 五、编辑席：只在两个节点问诊，不作常设

| 节点         | 问什么                                                            | 为什么不常设                   |
| ---------- | -------------------------------------------------------------- | ------------------------ |
| 英文稿成型后、投稿前 | desk-check：scope 是否合适、体裁是否站得住、篇幅是否超、图表与伦理声明是否齐 | 判的是成品；对未成品判只会得到"还不到投稿水平" |
| 收到返修意见后    | 哪条必须全接、哪条可以有理据地顶回去、response letter 怎么定位                        | 一次性决策，不需要每轮复述            |

常设编辑席的副作用：每一轮都收到一个"这稿子还不够格"的判决，逼人回到无限润色。

## 七、开工前五问

1. 读者席工具里有没有多勾「文件系统」或「编辑」？
2. 读者席到底看到了什么？只给了正文，还是顺带能读到台账、纲要、往轮裁决表？
   冷读由"给它什么"决定，不由"用哪个模型"决定。实测：直接问它"这个项目在研究什么"，
   答得出就是没冷（独立上下文只管住记忆，管不住你主动递过去的文件）。
3. 本轮授权单位与体量写死了吗？没写死不许开工。
4. verdict.md 里有没有一条「不改」是拿项目历史当理由的？有，重判。
5. 结构轮与措辞轮分开了吗？没分开先拆。

## 九、TRAE 席位配置：何时调用 ＋ 工具／MCP

### 9.1 总原则

1. **「何时调用」写的是触发条件，不是职责描述。** 主控靠这一栏决定派不派活；写成职责，它会在不该派的时候也派。
2. **每栏必须带一条"不用于"。** 没有反面，主控会把写作活派给读者、把核对活派给执笔。
3. **示例里放中文原话。** 你实际怎么说，示例就该长什么样，否则匹配不上。
4. **MCP 默认全关。** 哪一轮需要哪项就临时开，用完关掉。MCP 是能力扩张，扩张就扩大泄漏面。
5. **工具即权限**：三个席位做到零写权限，只留执笔一个出口。

### 9.2 工具勾选矩阵

内置五项：阅读｜编辑｜终端｜预览｜联网搜索。MCP 各项以你的 TRAE 已装列表为准，默认全关。

| 席                | 阅读 | 编辑 | 终端 | 预览 | 联网搜索 | 全部 MCP |
| ---------------- | -- | -- | -- | -- | ---- | ------ |
| `cold-reader`    | ✔  | ✘  | ✘  | ✘  | ✘    | 全 ✘    |
| `paper-reviewer` | ✔  | ✘  | ✘  | ✘  | ✘    | 全 ✘    |
| `ledger-auditor` | ✔  | ✘  | ✘  | ✘  | ✘    | 全 ✘    |
| `drafter`        | ✔  | ✔  | ✔  | ✘  | ✘    | 全 ✘    |

三条必须照做：

- **读者席「联网搜索」必须关。** 开着的读者会去查期刊 scope、查最新进展，然后开始"这样写可能不被接收"——冷读当场失效。
- **Computer Use 全程关。** 它是桌面控制权，等于一条绕过「编辑」开关的后门；开了它，"只读"就只是口头约定。
- **对账席别勾「终端」。** 终端是写权限的旁路。改由**主控跑脚本、原始输出落盘**（`reports/_raw/mas/r<N>/raw_*.txt`），对账席只读正文、台账与这些落盘件。
  - 退路：若确实要让对账席自己跑命令，则勾终端，并接受"只读"降级为白名单约定＋法官复核原始输出。

`pdf-reader-mcp` 只在做"引文撑不撑得住"核对的那一轮临时开；文献库类 MCP 只在补中文文献那一轮开；`review-report`／`deployment`／`github` 等与写作无关的**全程不需要**。`预览` 四席都不需要。

### 9.3 四个席位的「何时调用」填法

**`cold-reader`**

```
Use this agent when the user asks for a pure cold read of the manuscript — a located record of where a first-time reader stumbles — and does not want suggestions or evaluations. Give it the manuscript file only; never the ledger, outline, or receipts.

Examples:
- Context: 改完一批，想确认这一版还有没有绊点，且不要建议
  user: "读一遍这版正文，只告诉我你在哪绊住的，别给建议"
  assistant: "调用冷读者，出绊点记录"
- Context: 冻结或投稿前做最后一次陌生读者通读
  user: "这版要冻了，先当没看过的人读一遍"
  assistant: "调用冷读者做冻结前冷读"

Do NOT use for: 提修改建议、评价学术价值、需要项目背景的核对、文字润色。
```

**`paper-reviewer`**

```
Use this agent when the user wants a reviewer-grade judgment on whether the manuscript's claims are supported by the evidence it cites, or wants to know what a journal reviewer would attack. Give it the manuscript only.

Examples:
- Context: 想知道结论站不站得住
  user: "这篇稿子的结论撑得住吗，以审稿人身份看"
  assistant: "调用审稿人席，出主张—凭据裁定表"
- Context: 投稿前预演审稿
  user: "模拟一次目标期刊审稿，会挑什么"
  assistant: "调用审稿人席做投稿前预演"

Do NOT use for: 文字修改、格式与体例检查、引用著录核验（那是对账席的活）。
```

**`ledger-auditor`**

```
Use this agent when the user wants a ledger check — citation coverage, table parseability, numeric consistency, bibliography numbering, frozen-region integrity, front-matter conformity — rather than a content judgment. It reads the manuscript, the ledger, and the raw command outputs already dumped to reports/_raw/mas/.

Examples:
- Context: 某批改动后要复核账
  user: "这批改完，核一下引用和表数"
  assistant: "调用对账席，出差异表"
- Context: 投稿前全面查账
  user: "投之前把账全查一遍"
  assistant: "调用对账席做投稿前总对账"

Do NOT use for: 判断论述是否成立、给写法建议、修改任何文件。
```

**`drafter`**

```
Use this agent ONLY when the user supplies an explicit itemized verdict list (or an explicit itemized edit list) and asks for it to be applied. A vague "改一下／润色一下" is NOT a trigger.

Examples:
- Context: 裁决表已出，按表落文
  user: "按这份裁决表落文，只改标了『改』的"
  assistant: "调用执笔席执行裁决表"
- Context: 结构轮已批准，执行搬移
  user: "结构轮按这个方案开，授权到节"
  assistant: "调用执笔席执行结构轮"

Do NOT use for: 决定改什么、评估改得好不好、没有清单时的"顺手优化"。
```

### 9.4 主控侧的派活顺序

主控（内置 Agent）自己没有「何时调用」栏，但要守住一条：**先跑脚本落盘，再派对账；先出裁决表，再派执笔。**
反过来做——先派执笔、事后补账——就是这批改动没有闸门。

**主控不建子智能体。** 它就是内置 Agent 本身，而且必须是它：官方限制只有内置 Agent 能调用自定义智能体。
把法官做成自定义智能体，它就调不动读者、对账与执笔，法官从"主控"退化成"顾问"。

法官规程的三种放法，取其一：

| 放法 | 做法 | 代价 |
|---|---|---|
| A 每轮开工贴一次（推荐） | 新开一轮，第一句把 §2.4 贴给主控 | 每轮多粘一次；但只在这一轮生效，不污染别的活 |
| B 写进项目 Rules 常驻 | 一次配好 | 你让它查文件、改脚本时，它也端着法官架子问"授权单位是什么" |
| C 做成子智能体只 @ 直呼 | 不勾「可被其他智能体调用」 | 它没有派活权，你成了人肉转发器 |

推荐 A：法官规程只在"跑轮"时成立，本来就不是常态。

每轮开头三句（直接粘）：

```
本轮按 docs/task_cards/多智能体写作体系.md §2.4 执行，你是主控兼法官。
先读 CLAUDE.md 的红线；再跑核验脚本，原始输出落 reports/_raw/mas/r<n>_<date>/。
然后 @ledger-auditor 出对账、@cold-reader 出冷读，你自己出裁决表，最后 @drafter 执行。
```

**触发词**：用户说「按多智能体模式开始工作」或「按多智能体模式协作」，即等同粘贴上面三句；主控自动按 §2.4 跑轮，不再逐轮粘。其他任务不触发本模式。

## 十、规则怎么喂：三层约束与席位的关系

### 10.1 TRAE 的实际机制（官方文档，2026-10 版）

| 层 | 加载方式 | 作用范围 | 出处 |
|---|---|---|---|
| `CLAUDE.md` | **设置级开关**，全量注入上下文 | 一旦开启，**所有**对话都带 | 设置 > 规则 > 导入设置 >「将 CLAUDE.md 包含在上下文中」 |
| `.trae/rules/` | 全量或按 globs／description 生效 | 项目级，可子目录嵌套（≤3 层） | `docs.trae.cn/ide_rules` |
| `SKILL.md` 类文件 | **按需读取**（工具读文件，不自动注入） | 谁读谁有 | 官方论坛说明：Rules 全量、Skill 按需 |
| 项目记忆 | 自动积累，项目内共享 | 所有对话 | 设置 > 规则与记忆 > 记忆 |

三条推论：

1. **`CLAUDE.md` 的开关不是按智能体分的。** 开，则冷读席也拿到项目史与全部红线；不开，则对账与执笔拿不到红线。
   **默认应当是关**——需要红线的席位，红线写进它自己的提示词；细则让它按路径去读。
2. **冷读席一旦读到 `CLAUDE.md`，冷读当场失效。** 它会知道"这段在冻结区"、"这条口径定过"，于是开始替作者辩护。
3. **项目记忆是共享的**，也会污染冷读。跑冷读那几轮，把记忆开关关掉，或至少不在正文讨论里让它"记住"任何东西。

### 10.2 分席投喂表

| 席 | 吃什么 | 不吃什么 | 量级 |
|---|---|---|---|
| 冷读 | 仅 `mas_agent_prompts.md` §一 | CLAUDE.md、两卷、台账、纲要、往轮裁决 | 0 |
| 审稿 | 仅 `mas_agent_prompts.md` §二 | 同上 | 0 |
| 对账 | 红1／红2／红3＋写§4.1 摘 20 行 | 写作卷其余、claims、concepts（除第八项的概念扫描） | ~2 KB |
| 执笔 | 红线 7 条＋写作卷路由表＋本轮涉及的 2–3 条 | 体系卷（除非本批动台账） | ~5 KB |
| 法官 | `CLAUDE.md` 红线段＋两张卡 | 文件指针与待办两段，按需查 | ~4.5 千字符 |

原则：**规则量与该席的破坏力成正比，与它的判断半径成反比。** 冷读没有写权限，破坏力为零，所以零规则；执笔是唯一能改坏文件的席，规则最全。

### 10.3 为什么不能全量投喂

三层规则合起来可达数万字符，正文也有数万字符。规则占上下文近四成时，会发生中段遗忘——被忘掉的正好是最需要的那几条纪律。每个席的规则预算都该有闸门。

另一个副作用是**裁决下沉**：提示词说"不改文件"、CLAUDE.md 说"交付后更新 progress"，两处不一致时，agent 会自己挑一个，且不告诉你挑了哪个。本该由法官做的裁决，被下沉到了执行层。

### 10.4 三十秒自检

每席开工第一句，让它自报三样：**我读了哪几个文件／我记得的三条红线／我这一轮不许做什么。**
答不出来或答错，说明规则没进去，这一轮不要开。
这一条比任何"请严格遵守"都有效——它把"有没有读到"变成可观测的事实。完整测法见 `mas_selftest.md`。

## 十一、开工六步与硬约束（正典）

```
# 多智能体工作模式（触发词）

用户说「按多智能体模式开始工作」或「按多智能体模式协作」，即自动按
docs/task_cards/多智能体写作体系.md §2.4 跑一轮，不再逐轮粘贴开工三句。
其他任务不触发本模式，不加载法官规程——避免常驻法官在查文件、改脚本时误问授权。

固定流程（缺一不可）：

1. 主控（内置 Agent，即唯一法官）读 CLAUDE.md 红线与任务卡 §2.4；扫 reports/_raw/mas/
   取最大轮次 N，建 reports/_raw/mas/r<N+1>_<YYYYMMDD>/。
2. 主控跑核验脚本，原始输出落该目录 raw_*.txt：引用覆盖、表结构、数字口径、台账、
   冻结区、门面、progress check。
3. 并行派 @ledger-auditor 出对账、@cold-reader 出冷读；对账席只读正文、台账与已落盘 raw，
   冷读席只给正文。两席产出由主控存为 audit.md／reader.md。
4. 主控出 verdict.md：对账条目判「必改／转用户」；读者条目五码
   （改／不改-条文／不改-论断／进结构队列／转对账）；同病灶 ≥3 次合并为结构级条目；
   表头写死授权单位与体量（措辞 ≤20 处、结构 ≤2 处；结构轮与措辞轮分开）。
5. 主控派 @drafter 执行裁决表标「改」的条目；执笔先备份、只动清单、跑四项核验
   （diff 行／引用多重集／pandoc 解表数／SHA 与字节）、出回执、按约定记 progress。
6. 主控复核执笔结果，报告本轮改了哪些、哪些进队列、哪些转用户。

硬约束：

- 冻结区只有用户能重开；任何席不得自称获授权。现行范围一律以 docs/freeze_register.md 为准（没有该文件时，以用户当轮明确指定的范围为准，并写进 verdict 表头）。
- 结构轮须用户先批「节」级授权；措辞轮不得夹带结构改动。
- 审稿席按 §三 每 2–3 轮或结构轮加跑；投稿前必跑；用户明确「只跑对账＋冷读」时从其指令。
- 开工自报：派任一子智能体时，prompt 第一段必须要求其开工第一句先自报三样——
  （1）我读了哪几个文件（逐个列路径）；（2）我记得的三条红线（每条一句话）；
  （3）我这一轮不许做什么（至少一条，指本席权限边界）。缺一视为未开工，主控退回重派；
  各席自报由主控摘录进本轮 verdict.md 的「席前自报」节，未自报的席位产出不采纳。
- 对账席、冷读席只读；执笔是唯一写入出口。
- docs/progress.md 只经项目约定的通道写入；改前备份、改后回执仍按红线 7。
```

> **增补三处（不属原段，六步之外）**：⓪ 开工先结 U 账（`mas_pending.md`）；
> ⑥ 收工除四项核验外，还须更新三本账（U账／冻结台账／progress）；审稿席在**结构轮前与投稿前必跑**。

## 十二、系统故障与补丁（源项目 r1–r3 复盘）

这一节不是文章问题，是**体系本身怎么装坏**。通用版保留，供自检时对照。

**1. 冷读席还在跑旧格式。**
症状：`reader.md` 只有三列表和自报，没有回味、没有悬置账。
根因：安装要拼三段（角色在流程卡、法条在规则卡、补丁在规则卡 §6.3），一拼就漏。
补丁：提示词只从 `mas_agent_prompts.md` 整段复制，粘一次到位。

**2. 边界错位：术语首现未定义挤占冷读。**
症状：冷读 41 条里 17 条是"先用后定义"，真正只有读者能给的东西被挤掉。
补丁：对账席加第八项「概念首现扫描」；冷读提示词写明"术语有没有先定义再使用，不记"。

**3. 转用户条目没有总账，同一件事被裁决了两轮。**
症状：同一冲突 r2 提、r3 又提；转对账的条目两轮没人核。
补丁：`mas_pending.md`（U 账）跨轮记「谁在等、等了多久」；连续两轮未决标「滞」，标滞的下一轮不许再以"转用户"结案。

**4. 冻结区成了意见的沉淀池。**
症状：转用户条目全落在冻结段，每轮都在冻结区前停一次。
补丁：把同一冻结区的条目合成一次「窄口重开批」，一次处理完；此后冷读从冻结区之后开始读。

**5. 法官凭记忆写"现状"。**
症状：裁决表里的"现状"与原句的转义形态、标点不一致，执笔停下。
补丁：二选一——`改-定句`（逐字原句＋目标句，原句必须从文件复制）或 `改-定向`（只给改什么、改到什么程度，句子由执笔拟）。写不出逐字串的，一律降为 `改-定向`。

**6. 机械修与落文混在一批。**
症状：diff 行数对得上，但回执读不出哪些是机械修、哪些是语义改。
补丁：两类改动**分批发、分开记**；SHA 链可以连续，批次号必须分开。

**7. 结构级条目合并过度。**
症状：一条结构条目里含三节，按"节"授权时无法执行。
补丁：合并判据是"同一论断／同一关系"；三件事各出现一次，就是三条。

**8. 五码不互斥。**
症状：同一条既判 `转对账` 又列进"转用户"。
补丁：一条只能有一个码；`转对账` 的去向是下一轮对账席，不是用户清单。
