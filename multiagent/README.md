# 多智能体协作模式（Trae 平台）

> 版本 1.0（2026-11-17）。把源项目跑了四轮的「多智能体写作体系」整理成通用版：
> 一个主控兼法官 + 四席分工（冷读／审稿／对账／执笔），席位之间靠文件传参，工具即权限。
> 本目录不被自动加载；用安装脚本或手动复制到**你的项目**后才生效。

## 0. 它解决什么

一篇长稿改到后期，最难的往往不是"再写一点"，而是三件事同时发生：

| 问题 | 单智能体硬改的后果 | 本模式的做法 |
|---|---|---|
| "读起来绊不绊"没人真读 | 模型边读边改，读感被改法覆盖 | 冷读席只读不改，先出 `reader.md` |
| "数字、编号、台账对不对"没人核 | 改十处措辞，顺手改坏三处账 | 对账席只报不改，出 `audit.md` |
| "结论撑不撑得住"没人问 | 自己写的自己判，越判越顺 | 审稿席只挑刺，出 `reviewer.md` |
| 谁来决定改什么 | 执行层自己裁决，裁决不留痕 | 法官只出 `verdict.md`，执笔只按表落文 |
| 改坏了怎么办 | 只能整文件回滚 | 按条可回退，`verdict.md` 是判断的账 |

**它不是"让五个 AI 一起写"，恰恰相反：只有执笔能写，其余三席物理上没有写权限。**

## 2. 安装

### 2.1 自动安装（推荐）

在仓库根目录运行。`-MultiAgent` 会把本目录的规则、任务卡与闸门脚本放进**项目**（不是 `~/.claude`），因为 `.trae/rules` 只在项目级生效。

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File install.ps1 -ProjectRoot D:\my_survey -MultiAgent
```

```bash
# macOS / Linux
bash install.sh ~/my_survey --multi-agent
```

装完的项目里多出：

```
<项目>/.trae/rules/mas-trigger.md
<项目>/docs/task_cards/多智能体写作体系.md
<项目>/docs/task_cards/mas_agent_prompts.md
<项目>/docs/task_cards/mas_rulecards.md
<项目>/docs/task_cards/mas_pending.md
<项目>/docs/task_cards/mas_selftest.md
<项目>/scripts/mas_gate.py
<项目>/CLAUDE.multiagent.snippet.md
```

**已存在的文件不会被覆盖**（尤其是 `mas_pending.md`，它是运行中的账）。更新模板时，先看一遍 `.new` 或手动对比。

### 2.2 手动安装

把上面列出的文件逐个复制到对应位置即可，没有编译、没有依赖（`mas_gate.py` 只用 Python 标准库）。

### 2.3 并入 CLAUDE.md

打开 `<项目>/CLAUDE.multiagent.snippet.md`，把内容并入项目 `CLAUDE.md` 顶部。若项目没有 `CLAUDE.md`，直接把该文件复制为 `CLAUDE.md`。

只做一次。之后 `CLAUDE.md` 是法官的红线来源，不再自动注入（见 §3.1）。

## 3. 在 Trae 里配置（零基础）

### 3.0 先理解拓扑

```
                  ┌───────────────────────┐
                  │ 主控／法官（内置 Agent） │  ← 唯一能改主意的地方
                  └───┬───────┬───────┬───┘
            ┌─────────┘       │       └─────────┐
            ▼                 ▼                 ▼
      cold-reader       paper-reviewer      drafter
       （冷读）            （挑刺）           （执笔）
       只开「阅读」        只开「阅读」        阅读+编辑+终端
                          │
                    ledger-auditor（对账，只读）
```

三条硬约束（Trae 官方机制决定）：

1. **只有内置 Agent 能调用自定义智能体**，自定义之间不能互调。所以法官必须是内置 Agent，不能做成自定义席。
2. **被调用时是独立上下文**：它拿不到你们在主对话里说过的话，只拿得到提示词和传给它的文件。席位之间靠文件传参。
3. **工具即权限**：只读席不勾「编辑」「终端」，它物理上改不了稿。

### 3.1 先关两个全局开关

在 Trae 设置里：

| 开关 | 设成 | 为什么 |
|---|---|---|
| 设置 > 规则 > 导入设置 >「将 CLAUDE.md 包含在上下文中」 | **关** | 开了会把项目史与全部红线灌给冷读席，冷读当场失效；法官需要时按路径读 |
| 设置 > 规则与记忆 > 记忆 | 可开，但冷读那几轮先关 | 项目记忆是跨席位共享的，也会污染冷读 |

找不到这两个开关也没关系：`mas_selftest.md` 第 0 步给了"一句话测出来"的办法。

### 3.2 建四个自定义智能体

在 Trae 的 AI 输入框里输入 `@` → 面板底部「创建智能体」。每个席按下面四行配置：

| 席 | 名称 | 英文标识名 | 勾「可被其他智能体调用」 | 提示词 |
|---|---|---|---|---|
| 冷读 | 冷读者 | `cold-reader` | ✔（填 §3.4 的「何时调用」） | `mas_agent_prompts.md` §一 |
| 审稿 | 审稿人 | `paper-reviewer` | ✔（填 §3.4） | `mas_agent_prompts.md` §二 |
| 对账 | 对账员 | `ledger-auditor` | ✔（填 §3.4） | `mas_agent_prompts.md` §三 |
| 执笔 | 执笔 | `drafter` | ✔（填 §3.4） | `mas_agent_prompts.md` §四 |

每席的提示词**整段复制、整段覆盖**，不要只粘角色段。粘完用 `mas_selftest.md` 第 0.5 步验首尾，防截断。

**别建法官智能体。** 法官就是内置 Agent 本身；做成自定义席，它就调不动其他四席了。

### 3.3 工具勾选矩阵

| 席 | 阅读 | 编辑 | 终端 | 预览 | 联网搜索 | 全部 MCP |
|---|:--:|:--:|:--:|:--:|:--:|:--:|
| `cold-reader` | ✔ | ✘ | ✘ | ✘ | ✘ | 全 ✘ |
| `paper-reviewer` | ✔ | ✘ | ✘ | ✘ | ✘ | 全 ✘ |
| `ledger-auditor` | ✔ | ✘ | ✘ | ✘ | ✘ | 全 ✘ |
| `drafter` | ✔ | ✔ | ✔ | ✘ | ✘ | 全 ✘ |

三条必须照做：

- **冷读的「联网搜索」必须关。** 开着的冷读会去查期刊 scope 和最新进展，然后开始"这样写可能不被接收"——冷读当场失效。
- **Computer Use 全程关。** 它是桌面控制权，等于绕过「编辑」开关的后门。
- **对账别勾「终端」。** 终端是写权限的旁路。命令由主控跑、原始输出落盘，对账只读落盘件。

MCP 默认全关。做"引文撑不撑得住"核对的那一轮，可临时开文献阅读类 MCP，用完关掉。

### 3.4 填「何时调用」

这一栏写的是**触发条件**，不是职责描述；末尾必须带一条"不用于"。示例里放你实际会说的中文原话。四段现成文案在 `多智能体写作体系.md` §9.3，直接复制。

### 3.5 触发词

安装脚本已把 `.trae/rules/mas-trigger.md` 放进项目。它只有几行、不含项目内容，`alwaysApply: true`，对所有对话生效。

在主对话（内置 Agent）里说：

> 按多智能体模式开始工作

即按 `多智能体写作体系.md` §2.4 跑一轮，不用逐轮粘法官规程。其他任务不会触发，避免法官在查文件、改脚本时误问授权。

## 4. 验收（十分钟）

按 `docs/task_cards/mas_selftest.md` 跑四步。**最低限度只验一条**：

> 问冷读席："你受本项目哪几条约束？"

答"零条"、且说不出项目背景，才算装好。答得出节点名、冻结范围、轮次编号——说明它还看得见项目，本轮作废。

其他三步：

1. **配置核验**：问任一席"这个项目在研究什么"，答"不在我的输入里"＝CLAUDE.md 注入已关。
2. **首尾校验**：让每席念提示词第一段与最后一句，防截断。
3. **越界诱导**：给一个"顺手改一下"的请求，看它停不停。

## 5. 跑一轮

```
⓪ 结账    主控读 docs/task_cards/mas_pending.md，把已决条目转本轮候选
① 冷读    @cold-reader      → reader.md（只给正文）
② 对账    @ledger-auditor   → audit.md（主控先跑脚本落 raw_*.txt）
③ 挑刺    @paper-reviewer   → reviewer.md（结构轮前／投稿前必跑）
④ 裁决    主控自己           → verdict.md（写死授权单位与体量）
⑤ 执行    @drafter          → 改后正文 + 回执
⑥ 复核    四项核验 + 三本账 + python scripts/mas_gate.py reports/_raw/mas/r<N>_<date>
```

一轮的全部产物落 `reports/_raw/mas/r<N>_<YYYYMMDD>/`。`mas_gate.py` 全部 PASS 才算收工。

停止规则：连续两轮新条目为 0，或与前两轮重复率 ≥70%，或本轮「改」≤2 且无结构条目——任一成立即收轮。

## 6. 常见问题

**冷读席知道项目背景，还在替作者辩护。**
CLAUDE.md 注入没关，或项目记忆开着，或你主动把台账／纲要递给了它。先跑 `mas_selftest.md` 第 3 步；软隔离无效就把正文复制到空目录，用 Trae 打开那个目录跑冷读。

**审稿席／对账席开始改字或给写法建议。**
先查工具（多勾了「编辑」或「终端」必越界），再查提示词措辞：把"不许"改成"遇到 X 立刻停止并回一句 Y"。

**提示词粘进去后行为不对，但看不出哪里错。**
大概率被截尾了。让该席念第一段和最后一句；末句缺了就是截断。重贴或把末尾几行单独补上。

**触发词不灵。**
先查 `.trae/rules/mas-trigger.md` 是否存在、文件头是否 `alwaysApply: true`；再查主控是否读到了它。Trae 版本不同，Rules 的加载位置可能不同。

**为什么不设常设编辑席？**
编辑判"收不收"，需要成品。草稿阶段它只会返回"还不到投稿水平"，把每一轮都拖回无限润色。编辑席只在英文稿成型后与收到返修意见后各问诊一次。

**这套东西和两卷 skill 冲突吗？**
不冲突。两卷管"怎么写、怎么核"，多智能体管"谁来写、谁来核、裁决怎么留痕"。规则卡 §二 已把每条法指派到席位，法官受全部，其余按需。

## 7. 与源项目的差异

源项目用的是焊接综述的具体口径：目标期刊、正文文件、表数、漏斗数字、冻结行号。通用版做了三件事：

1. **去掉项目事实**：正文文件、期刊名、行号、阈值全部换成 `<占位符>` 或 `【本项目口径】`。
2. **保留架构与判据**：星形拓扑、五席定位、五码裁决、八项对账、停止规则、清账闸、工具矩阵，一条没删。
3. **保留踩坑记录**：流程卡 §十二 的八条系统故障，是源项目 r1–r3 真实踩出来的，直接可用。

**你必须填的**：`mas_agent_prompts.md` §三 的【本项目口径】段。不填，对账席只能对格式、对不了数。
