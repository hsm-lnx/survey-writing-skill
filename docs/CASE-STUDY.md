## 0. 起点：一句话和三个约束

```text
我想写一篇激光焊接过程监测的中文综述，投《机械工程学报》，1.5 万字左右。范围还没想好。
```

这句话里有三个约束：**目标期刊**、**字数**、**范围待定**。前两个是硬约束，第三个要靠对话收敛。

环境准备按 [README §2](../README.md#2-五分钟上手) 五分钟装好；核心依赖只有 Python 3.8+ 和网络，Zotero / AMiner / 邮箱 Alert 都是可选项。装完后在项目目录打开 Claude Code，直接说上面这句话即可——不用记脚本。

## 1. 第 1 轮：把模糊题目收敛成范围

```text
你：我想写一篇激光焊接过程监测的中文综述，投《机械工程学报》，1.5 万字左右。范围还没想好。
它：先确认三件事——读者是焊接工艺方向还是控制方向？要不要覆盖增材制造？时间窗近十年还是十五年？
你：工艺方向；覆盖增材；近十年。
它：给出章节总纲（6 章），标出每章要回答的问题和大致篇幅，等你确认。
```

这一步的产物是**章节总纲**，不是正文。总纲长这样（示意）：

| 章节 | 要回答的问题 | 参考篇幅 |
|---|---|---|
| 1 引言 | 为什么过程监测是焊接质量控制的瓶颈 | 1500 字 |
| 2 工艺分类与监测需求 | 不同焊接工艺对监测信号的要求差在哪 | 2000 字 |
| 3 信号采集与特征提取 | 有哪些信号通道、怎么转成可用特征 | 3500 字 |
| 4 缺陷识别与模型 | 从特征到缺陷判别的模型路线与证据 | 3500 字 |
| 5 闭环控制与工程应用 | 监测结果如何用于实时调控、落地到什么程度 | 2500 字 |
| 6 总结与展望 | 现有证据的边界与未解问题 | 2000 字 |
| **合计** | | **15000 字** |

你可以直接改：删一章、合并两章、调顺序，它会按你的意见重排。

## 2. 第 2 轮：建文献库

```text
你：就按这个总纲，先把第 3 章的文献收进来。
它：把第 3 章拆成若干检索方向 → Crossref 查 DOI 和书目、arXiv 查预印本、
    中文文献和无 DOI 老文献走 AMiner → 逐条核验 → 追加进 bib/verified.md，
    编号从当前最大号顺延 → 交一份清单：新增多少、存疑多少、查无多少。
```

几个关键纪律：

- 查不到的条目标 `[待验证]`，**不编 DOI、卷号、页码**；
- 每条查询的原始返回落盘 `reports/_raw/`，以后可复查；
- 已有条目只读、不重验；新增编号从当前最大号顺延；
- 检索动作由 Claude Code 调公开接口完成，skill 规定的是「查什么、怎么验、怎么记账」。

## 3. 第 3 轮：搭章节骨架

```text
你：第 3 章按「信号类型 → 特征提取 → 缺陷识别」这条线搭骨架。
它：给出段落提纲——每段一句论述指向、拟引用的台账编号、哪些位置需要新增文献
   → 你确认后才动笔。
```

段落提纲是整套流程最关键的闸门。没有提纲就开写，结果一定是「文献罗列段」。示意：

| 段落 | 论述指向（一句话） | 拟引台账编号 | 待补 |
|---|---|---|---|
| 3.1.1 | 视觉与声学信号在监测对象上互补，不能互相替代 | [7][12] | 需补一篇中文工艺研究 |
| 3.1.2 | 电信号响应快但受飞溅干扰，适用边界要写清 | [15][18] | — |
| 3.2.1 | 时域统计特征可解释性强，但跨工艺迁移差 | [21][24] | 需一条强论断的第二篇支撑 |

确认之后才进入写作。

## 4. 第 4 轮：填血肉

```text
你：按提纲写 3.2。
它：从本节证据池取文献 → 用【作者 年份】占位写 → 做删引测试 → 把占位替换成 [n]
   → 交本节引用明细表：每条文献的占位、台账编号、支撑哪句话、A/B/C 依据等级。
```

写作时每条引用**先写占位、不写编号**；整节定稿后统一挂编号，避免中途增删导致全文编号漂移。小节交付时附一张引用明细表（示意）：

| 占位 | 台账编号 | 支撑哪句话 | 依据等级 |
|---|---|---|---|
| 【Zhang 2021】 | [21] | 时域统计特征可解释性强 | A（全文关键句） |
| 【Li 2022】 | [24] | 跨工艺迁移差 | B（仅摘要，待取全文） |

B 级不能撑中／强论断——要么补全文升 A，要么把措辞降级。

## 5. 第 5 轮：自检与交付

```text
你：核一下 3.2，哪几条撑不住「主流」这个说法。
它：把「主流」这类中/强论断逐条对回原文和证据等级；
   撑不住的给出两条路：补证，或把措辞降级。不会直接放行。
```

能机械检查的部分直接跑脚本（`0` 才算过）：

```bash
# 正文引用覆盖
python .claude/skills/survey-ops/scripts/cite_coverage.py 正文.md -m "# 参考文献"

# 忠实性证据行校验
python .claude/skills/survey-ops/scripts/faithfulness_check.py 证据表.md -c 正文.md
```

**交付清单**（每一条都应能在项目里找到对应文件）：

- [ ] 正文稿件 `manuscript/`
- [ ] 核验台账 `bib/verified.md`
- [ ] 引用明细表与证据表
- [ ] 引用覆盖报告、结构体检表
- [ ] 查询原始返回 `reports/_raw/`（可复查）

## 6. 回头看：这套流程真正省掉的是什么

1. **不会编文献**：查不到就是查不到，标 `[待验证]`，原始返回落盘。
2. **编号不漂**：正文号与台账号双轨，变动走 diff 报告。
3. **论断有边界**：中／强论断必须有对应等级的证据，不靠「感觉」放行。
4. **能接着做**：台账、提纲、进度板都在项目里，换会话、换机器、隔一周回来继续。

它不是「一句话出整篇」的黑箱——章节总纲、段落提纲、结构改动、强论断，这几处都会停下来等你确认。
